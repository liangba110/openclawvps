### 关键修复：DSL 变量引用格式（2026-07-17 11:18-11:28）
- **问题发现**：工作流运行后，DeepSeek 输出"用户没有提供具体产品信息"，且通义万相收到的 prompt 不正确
- **根因**：DSL YAML 中变量引用写成了 `{#start.product_name#}`（单花括号），但 Dify 1.16 要求 `{{#start.product_name#}}`（双花括号）
- **验证**：通过 Dify UI 运行的截图中，LLM 节点的 user prompt 显示 `{#start.product_name#}` 没被替换为实际值
- **Dify 源码确认**：`PromptTemplateParser` 中的正则 `WITH_VARIABLE_TMPL_REGEX` 匹配的是 `\{\{#...\}\}`（双花括号+井号）
- **YAML 陷阱**：在 f-string 中写 `{{#...#}}`，Python 转义后输出为 `{#...#}`
  - 解决方案：用行级字符串拼接构建 YAML，或在 f-string 中写 `{{{{#...#}}}}` 得到 `{{#...#}}`
- **修复结果**：修复后 LLM 正确识别了"便携式蓝牙音箱"，通义万相也收到了正确的绘图提示词
- **验证结果**：通义万相成功生成了蓝牙音箱图片，docker zip 已打包到下载链接
- **工作流 DSL 最终版本**：`/tmp/fixed_v3_workflow.yaml`
