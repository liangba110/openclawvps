## 下载链路三大 Bug 修复（老板 19:58 要求排查，20:15 ✅）

### 背景
老板查看 ai-painting 购买资料包后，发现归档日期（08-10）与正文更新时间不一致，要求排查刷新/归档链路。排查后发现不只是归档问题，还有两个更严重的隐藏 Bug。

### Bug 1：extractTOC 正则不跨行 → 多行 h2 全丢
- 正则 `.*?` 不匹配换行（缺 s flag）
- ai-painting 等产品的 h2 是多行格式 `<h2>\n<span class="chapter-num">1</span>\n标题...` → 5 个 h2 全部匹配不到
- ai-crossborder 等单行 h2（`<h2 id="ch1">`）正常 → 这就是卡片目录不一致的真正根因（之前 store 页修复只做了降级显示，没修根因）

### Bug 2：download 路由找不到归档 → 用户下载到错误内容（最严重）
- refresh 生成的归档是 `slug-2026-08-10.tar.gz`（带日期）
- download 路由只找 `slug.tar.gz` / `slug.zip`（不带日期）→ 找不到 → 走 fallback **拼接全部 41 篇文章**，根本不是产品资料包！

### Bug 3：seed.mjs 生成假 zip
- `tar -a -cf xx.zip`：GNU tar 不认识 .zip 后缀，产出未压缩 tar 归档但叫 .zip（file 实测确认）
- 用户下载后打不开

### 修复
1. 三处 extractTOC 正则 `.*?` → `[\\s\\S]*?` + 空白归一化（store/page.tsx、[slug]/page.tsx、refresh/route.ts）
2. 重写 download 路由：findLatestArchive 按 mtime 匹配最新带日期归档 → 回退不带日期 → 按扩展名设 Content-Type → fallback 改用产品自身 full_content（不再拼接全部 posts）
3. seed.mjs 改用真 zip 命令
4. 数据修复：用修复后正则重建 12 个产品 toc_json（ai-painting 现在 h2=5）+ 重建 3 个假 zip 为真 zip
5. npx next build（198 页）+ pm2 重启
