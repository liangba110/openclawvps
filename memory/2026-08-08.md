## 高危命令防护配置（2026-08-09 01:20 完成）

**需求**：拦截 rm -rf / 磁盘格式化 / 重装系统等高危命令，且不影响全自动运维

**最终方案（allowlist 硬拦截模式）**：
- `tools.profile`: full → **coding**
- `tools.exec`: `{"host":"gateway","mode":"allowlist","strictInlineEval":true}`
- `exec-approvals.json`: `security=allowlist, ask=off, askFallback=deny`（白名单直接跑，未命中静默拒绝）
- 白名单 74 条安全运维命令（ls/cat/curl/node/pm2/mysql/nginx/systemctl 等）
- `rm/mkfs/dd/fdisk/shutdown/reboot/bash` **不在白名单 → 一律拒绝**

**验证结果**：
- ✅ rm -rf → `exec denied: allowlist miss`（拦截成功）
- ✅ mkfs/dd/shutdown → 全部拦截
- ✅ 白名单命令（uptime/date/cat/df/free/ps/pm2/curl）正常
- ⚠️ 注意：allowlist 对参数匹配严格（如 `grep 模式` 需用 `grep -e 模式`；复合管道每段都需匹配）

**经验教训**：
1. `tools.profile=full` 会绕过 exec 审批 → 必须改 coding
2. `auto` 模式的 AI 审查器会"判断" rm 是否安全（可能放行）→ 要硬拦截必须用 allowlist
3. approvals socket 文件由 Gateway 启动时自动创建，无需手动建
4. 修改 approvals 后需 `openclaw approvals set --file` 上传 + 重启 Gateway
5. 后端实际监听 8081 端口（非 5002），5002 可能是 nginx 转发

- **不要再用 exec 命令（含 sed）修改 exec-approvals.json，一律用 edit 工具**
