# MiMo 缓存优化指南

## 原理
MiMo-V2.5-Pro 输入定价：
- **缓存命中**：¥0.025/百万 token（极便宜）
- **缓存未命中**：¥3/百万 token（120倍差距）
- **输出**：¥6/百万 token

## 缓存自动触发条件
Hermes 的 prompt_caching 已开启（cache_ttl: 5m）。同一会话内，**相同前缀的消息会自动缓存**。

## 优化策略

### 1. 长任务拆多轮（而非一次性）
- ✅ 正确：同一个会话内，分多次小步骤完成（复用缓存前缀）
- ❌ 错误：每步开新会话（每次都重新注入完整 system prompt）

### 2. 系统提示稳定
- 避免频繁修改 MEMORY/skills（系统提示变化会破坏缓存）
- 批量操作记忆（一次 memory call 改多条）

### 3. 利用 1M 上下文
- 大项目审计：一次读完整个代码库（1M 上下文够用）
- 不用分多次会话读（每次新会话都重新付费）

### 4. Cron 任务成本低
- Cron 任务独立会话，每次完整注入 system prompt
- 但 MiMo 缓存命中价格低，每周整理 cron 成本可忽略

### 5. 工具调用保持稳定
- 避免中途切换 toolset（会破坏 prompt 缓存）
- 需要新工具时，下个会话再启用

## 成本对比
| 操作 | MiMo-V2.5-Pro | DeepSeek-V4-Flash |
|------|---------------|-------------------|
| 1M token 输入（缓存命中）| ¥0.025 | ¥0.5-1 |
| 1M token 输入（未命中）| ¥3 | ¥1-2 |
| 1M token 输出 | ¥6 | ¥2 |

结论：**MiMo 缓存命中后，长上下文分析几乎免费**。充分利用这一特性做深度工作。
