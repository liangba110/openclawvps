# BUG 修复优先级清单（用户提交时的标准模板）

## 用户交付清单结构

当用户用结构化清单交付 BUG 时，按 P0/P1/P2 分级修复，每项完成后 commit 写明 `BUG-XXX 描述`。

## 模板示例

```markdown
## 🐛 BUG 修复清单

### 🔴 P0 严重
- **BUG-001 搜索功能缺失**
  - 问题：首页搜索框点击直接跳列表页，没有搜索输入功能
  - 影响：核心功能缺失
  - 建议：实现搜索页面，支持按昵称/游戏/标签搜索

### 🟡 P1 重要
- **BUG-003 收藏无视觉反馈**
  - 点击收藏按钮后无状态变化和提示

### 🟢 P2 一般
- BUG-006：所有陪玩师都是默认头像
```

## 处理流程

1. **认领任务** - 用户说"从 P0 开始"时按编号顺序处理
2. **每项独立 commit** - 写明 `BUG-XXX 简述`
3. **修复后立即报告** - 告诉用户完成了 BUG-XXX，可继续
4. **遇到新 BUG 加入清单** - 如果修复过程中发现新问题，添加为 BUG-NNN

## 输出格式

```
**BUG-001 ✅** 已修复 `ec178d8`
**修复内容：**
- 列表页顶部搜索框
- 后端 SQL：昵称/段位/标签 三字段模糊匹配
- 实时搜索 + ✕ 清空

http://... 试试输入「王者荣耀」搜索。

要继续 **BUG-002** 吗？
```

## 关键原则

- **不要批量修复后报告** - 每项完成立即同步
- **P0 必须全修完** - 不可跳过
- **P1/P2 可分批** - 用户可随时切换
- **每个 BUG 一个 commit** - 方便回滚
