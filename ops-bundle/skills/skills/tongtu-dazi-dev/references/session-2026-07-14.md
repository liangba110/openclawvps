# Session 2026-07-14: 微信登录、实名认证、1Panel Nginx 配置持久化

## 1Panel 管理 Nginx 配置终极方案

1Panel 会恢复对 `sites-enabled/` 的写入。手动创建独立文件（`ttdazi`）会被还原为旧内容。

**已验证可行的方案**：将新站点配置写入现有文件 `huizhiyunma`（1Panel 不管理）：
```bash
cat > /tmp/ttdazi.conf << 'NGINX'
# 原 huizhiyunma 全部内容 + 新增 server 块
NGINX
sudo cp /tmp/ttdazi.conf /etc/nginx/sites-enabled/huizhiyunma
sudo nginx -s reload
```

注意：`sites-enabled/huizhiyunma` 是**独立副本**（非软链接），直接改它。改 `sites-available/` 不影响生效配置。

## 多域名 HTTPS + `default_server` 冲突

添加新域名时，若已有站点设 `default_server`，新域名 SNI 会被旧证书拦截。

**验证 SSL 证书是否正确**（配置被还原的最明显症状）：
```bash
openssl s_client -connect dazi.openai2000.cn:443 -servername dazi.openai2000.cn </dev/null 2>&1 | grep 'subject='
# 正确应为 CN = dazi.openai2000.cn；若显示 CN = openai2000.cn，说明配置被还原
```

## 微信 OAuth 关键坑点

| 问题 | 修复 |
|------|------|
| `user` 表缺 `wx_openid` 列 | `ALTER TABLE user ADD wx_openid VARCHAR(64); ALTER TABLE user ADD INDEX idx_wx_openid (wx_openid);` |
| `cur` 在 `with` 块外使用 | 所有 `cur.execute()` 必须在 `with conn.cursor() as cur:` 块内，查完后用变量保存结果 |
| `decode_token()` 不存在 | 实际函数名是 `decode_token()` 不是 `verify_token()` |
| OAuth 回调后获取 access_token 需 IP 白名单 | 在公众号后台添加服务器 IP |

## 手机号绑定三种方式

| 方式 | 后端接口 | 需要验证码 | 适用场景 |
|------|---------|-----------|---------|
| 手动输入+验证码 | POST `/api/wechat/bind-phone` | ✅ | 普通登录 |
| 微信快速验证 | POST `/api/wechat/wxphone` | ❌ | 公众号认证服务号 |
| 手动输入无验证 | POST `/api/wechat/bind-phone-simple` | ❌ | 不验证真实性 |
