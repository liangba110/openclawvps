# 同途搭子项目 · 用户偏好与常见陷阱

## 交互协议
- 首回复：**"老板收到，开始安排任务！"**
- 末回复：先发任务结果，**再单独发一条** "老板，任务执行完毕，请您审核！"
- 所有 Toast 信息非空
- 用户仅指出问题，不自诊断 → 立即查根因修复

## Toast / catch 规范
- 静默 catch（`refreshCaptcha` 等初始加载）：不弹 Toast
- 用户操作 catch：必须弹 `safeToast(e?.message || "操作失败")`
- 批量修复时注意区分 silent vs user-action catch

## 密码验证
- `PWD_MIN_LEN = 6`（非 16），仅含数字，不要大小写/特殊字符
- 前后端验证一致，否则 500

## 邮箱注册陷阱
- 邮箱 = `name + '@' + domain`（域名不含 @）
- 邮箱注册直调 send-email-code，不弹公众号二维码
- 注册按钮禁用仅 `loading`，字段验证在 doRegister() 内弹 Toast

## 审计方法论
- 子代理并行审计（前后端分离）
- 先扫全部路由/文件清单，再逐文件检查
- 输出结构化问题清单（🔴🟡🟢）
- 按优先级逐个修复，最后部署验证
