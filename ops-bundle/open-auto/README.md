# Open Auto — 全自动智能运维方案

> 腾讯云 VPS 全自动运维框架，巡检→检测→修复→验证→通知，闭环自治。

## 架构

```
┌─────────────────────────────────────────────┐
│              Open Auto 运维框架              │
├─────────────┬───────────────┬───────────────┤
│  L1 心跳    │  L2 数据      │  L3 业务      │
│  watchdog   │  db_guard     │  toc_guard    │
│  每分钟     │  每分钟       │  每小时       │
├─────────────┴───────────────┴───────────────┤
│              修复引擎（闭环）                │
│  检测 → 修复 → 二次验证 → 标记             │
├─────────────────────────────────────────────┤
│              通知策略（降噪）                │
│  修复成功=静默  失败/反复=QQ通知            │
└─────────────────────────────────────────────┘
```

## 巡检脚本

| 脚本 | 频率 | 职责 |
|------|------|------|
| `watchdog_notify.sh` | 每分钟 | PM2进程存活 + 站点HTTP 200 |
| `db_guard_notify.sh` | 每分钟 | DB完整性 + WAL落盘 |
| `toc_guard_notify.sh` | 每小时 | store产品TOC完整性 |
| `schedule-runner-cloud.cjs` | 每5分钟 | 定时任务调度器 |
| `domestic_intel_notify.sh` | 每天3:00/15:00 | 国内情报推送 |

## 通知策略

| 级别 | 触发条件 | 通知方式 |
|------|----------|----------|
| 🔴 严重 | 站点挂了 / DB损坏 / 修复失败 | 立即QQ通知 |
| 🟡 警告 | 自动修复成功 | 仅写日志，不通知 |
| 🟢 正常 | 全部OK | 静默 |

## 防死循环机制

- 同一问题24h内修复超过5次 → 升级为🔴严重告警，通知人工介入
- 幂等性检查：修复前先检测是否真的需要修
- 修复计数器：基于 `/tmp/toc-guard-fix-count.json`

## 依赖

- Node.js >= 18
- Python3（用于计数器状态管理）
- PM2
- bash
